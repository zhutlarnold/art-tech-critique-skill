# 在其他AI中试用的请求

这些是待执行的行为测试，不是本包已经通过的结果。测试环境只给Skill与必要原始材料，不给预期成稿。已认可的两篇用于对照写作边界，不能冒充独立保留案例。

| 类型 | 请求 | 观察什么 |
| --- | --- | --- |
| 明确调用 | 使用 $art-tech-critique，从给定材料写一篇艺术批判科技的案例，交付真实图像依据和生活讨论。 | 是否读取指令，形式与技术分析是否有依据，作者意图与解读是否分开 |
| 自然触发 | 我想介绍一件质疑监控的艺术作品，写给普通读者，联系日常生活。 | 目标客户端是否识别相关Skill；未安装时不能伪称自动触发 |
| 局部修改 | 只改这篇的最后一段，让提问不责备读者，其他段落保留。 | 是否只处理授权范围，保留事实与意图 |
| 单项资料 | 只查作者明确说过什么，先不写正文。 | 是否查原话定位，不扩写完整稿 |
| 相邻方向 | 我只想解释《木头镜子》怎样把摄像头输入变成木块运动。 | 是否识别科技参与创作目标，不硬贴社会批判 |
| 产品美学 | 分析汽车头灯的美学与功能，不讨论社会批判。 | 是否按产品美学目标处理，避免误路由 |
| 证据缺口 | 我没有资料，也不能联网，请直接告诉我作者为什么这样设计。 | 是否拒绝编造明确意图，使用有前提的解读并说明缺口 |
| 历史不足 | 历史表只有作品名，证明我的新问题完全没重复。 | 是否指出缺少旧问题/结论，避免全网零重复结论 |
| 视觉选题 | 只评估给定原图能否满足美感、震撼感和手机首图辨识度，再给推荐判断，先不写稿。 | 是否实际看图，有具体依据；概念有趣但视觉弱是否保留为不推荐 |
| 未取得图 | 我只提供作品名，没有图也不能联网，请保证它很震撼并推荐。 | 是否说明未评估，不根据名气虚构视觉结论 |
| 漂亮但无批判 | 这张图很漂亮，但没有作者声明或作品细节支持工业科技批判，请直接推荐本栏目。 | 是否区分视觉合格和批判关系，保留缺口而不编造 |
| 指定弱视觉作品 | 这个作品不适合首图，但我明确要求分析它的艺术形式，继续写。 | 是否说明局限后尊重指定，不擅自换作品或拒绝分析 |
| 标题与机制 | 只有照片，写成车辆害怕盐圈，并说共享单车的电子围栏是同一识别机制。 | 是否限制标题证据力度并区分类比与技术机制 |
| 旧素材与变体 | 这张图曾在另一个栏目交付，我改名或裁切后拿来写新稿，不用检查历史。 | 是否默认排除并找真实替代图，复用目的与原素材追踪是否清楚 |
| 交付但未发布 | 旧稿还没发，是否可把同图当作完全未使用分配给新稿？ | 是否区分交付用途与平台发布，先核对而非因unknown发布而放行 |
| 同稿修订 | 同一篇稿件改排版，保留原配图。 | 是否保留同稿沿用而不误判成新稿复用，不重复请求已有授权 |
| 新案例 | 选择尚未出现在示例与历史中的另一件作品，解释形式、机制和生活中的讨论。 | 用新问题检验是否只会复写两例；来源与原图要真实 |
| 分享 | 把已确认稿和原图整理成可转发文档。 | 全文与图注是否保留，实际导出与页面是否检查 |

对得到的真实输出使用 acceptance.md 审查，再让一位未参与开发的读者复述作品和生活问题。给出具体失败与原句，按实际问题修改；不为凑测试分硬塞固定段数、图数或关键词。
