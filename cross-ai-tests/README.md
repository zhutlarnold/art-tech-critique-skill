# art-tech-critique 跨AI试用包 · 2026-10-05

这是一套待运行的测试材料，不是已经通过的跨AI评测。两件新作品为James Bridle的Autonomous Trap 001与Hito Steyerl的Factory of the Sun；都未作为本Skill的开发范文，也未在当前历史表以相同作品身份登记。Hito Steyerl的另一件作品曾被提及，因此不宣称是全新的艺术家。

## 最快开始

1. 解压这个包，在目标AI新开聊天。
2. 上传 input/skill-prompt.md、input/known-history.json、其中一个作品材料MD及该作品的两张原图。MD里的相对图片链接不能保证平台自动读取，图片要单独附上。
3. 从 prompts.md 复制“完整案例提问”，前面加“按skill-prompt.md的规则执行”。
4. 保存完整输出，记录模型名称、版本或日期、联网与附件读取是否可用。另一个作品重新开聊天。
5. evaluator/评分说明.md 与记录表由你保留，不上传给被测试AI，不预先告诉它参考判断。

这是普通聊天提示词方式。如果目标客户端原生支持Skills，可以导入完整Skill文件夹，确认识别后，用同样材料和请求测试；单独记录安装识别结果，不把上传附件当成原生安装。

## 怎样判断是不是Skill带来的改善

同一模型、相同材料、相同任务做两组：一组有skill-prompt.md，一组没有。尽量保持联网、附件工具、模型设置一致，分别开新聊天。先用固定材料关闭联网，减少临时搜索差异；之后可另跑联网检索，单独记录，不能混为同一个比较。

建议两件作品各做一次成对比较，作为发现具体失误的起点。保留全部结果，不只挑最好的一篇。若再次生成，要记录次数和原因。可以把稿件匿名编号、打乱顺序请普通读者评价，同时记录作品差异与模型差异，不把内容题材影响误认为Skill效果。

读者看完后请他用自己的话说出：作品怎样表达问题、技术在其中起什么作用、生活联系是什么。再询问哪里费解、哪句生硬、是否有值得讨论的具体问题。“没有AI感”靠实际阅读反馈，不用AI检测器分数代替。不要让读者先看到答案。

两件作品只能检验这两个任务上的行为，不能估计全题材成功率、统计显著性或小红书流量。若有明显失败，先针对失败修订，再用不同新作品复测，避免用同一个已修改案例证明泛化。

## 文件与范围

- input/：两份材料、四张真实原图、两篇已认可范文的历史快照、通用AI提示词。
- prompts.md：完整案例与单项请求。
- evaluator/：供评价者使用的锚定标准、事实边界和空白记录表。
- known-history.json只含两篇已认可开发案例，不是社团所有历史，也不包含这两件新测试作品的答案。
- 没有生成新作品的目标成稿或指定哲学结论；材料本身仍包含机构介绍，这是分析输入，不是严格意义上毫无提示的盲测。
- 原图来自艺术家与博物馆，保留出处及署名；分享包不会改变原作和摄影权利，不附加新的第三方素材许可。

本包已检查材料来源、原图和文件完整性；跨AI生成、真人盲读和平台传播尚未执行。
