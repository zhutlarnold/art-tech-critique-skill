## SKILL.md


# 艺术批判工业与科技

从两篇经用户审阅认可的《Oil》与《ImageNet Roulette》案例提炼，并根据真实试用反馈补入视觉选题筛选。目标是先让作品原图有观看吸引力，再让普通读者看懂它怎样表达批判，并能联系自己的生活继续思考。默认中文；已有用户稿件、篇幅、素材与平台要求优先。调用示例与功能对应表见 [README](https://github.com/zhutlarnold/art-tech-critique-skill/blob/main/skills/art-tech-critique/README.md)。

## 按实际请求工作

选题先看图筛选，再给候选、问题和差异；视觉筛选只判断图像适配，不写正文；资料核查只核对主张；作者意图只查声明与访谈；配图只交付真实图片及用途；修改只处理指定问题；查重先给比较判断。用户要求完整案例时才组合研究、写作、选图与交付。

以作品如何处理工业或科技的影响为主线。主题可涉及环境、劳动、监控、数据分类、消费、身体或社会关系，但不能仅凭题材认定作者反科技。若请求主要关心技术怎样构成艺术语言，或产品的美学与功能，说明相邻方向的差别，按用户选定角度处理，不强行转成本栏目。

只做案例分析。交付稿件不等于发布；安装、上传 GitHub 和操作社交账号按任务中的实际授权执行，不从调用本 Skill 推导授权。

## 先确定旧问题和新问题

读取用户给定历史；未指定时查当前项目 `case-research-state/registry.json`。无文件就用 [空模板](https://github.com/zhutlarnold/art-tech-critique-skill/blob/main/skills/art-tech-critique/assets/registry.template.json)，不要把缺失历史当作从未写过。

核对作品名、已知别名、作者、版本及旧稿核心问题、结论、形式策略和讨论问题。跨栏目共用同一作品 ID，逐篇保留 `analyses`；换作品、换词或换栏目不等于论点新颖。研究前说明本次新增价值，完成后再比一次实际结论。细则与辅助命令见 [历史与查重](https://github.com/zhutlarnold/art-tech-critique-skill/blob/main/skills/art-tech-critique/references/history-and-dedup.md)。

## 素材复用限制

新稿选材前读取 [素材防重复规则](https://github.com/zhutlarnold/art-tech-critique-skill/blob/main/skills/art-tech-critique/references/material-reuse.md) 和跨栏目的项目总表。已交付/已发布稿用过的原图、截图、视频或同源变换素材，默认不能再次用于新稿；改名、裁切、压缩或截取同片不作为新素材。脚本出现image_reuse预警时先停止分配该素材，核对旧用途，寻找未使用的真实替代素材。

同一篇修订可沿用；用户明确指定比较或复用时按已有授权记录原因后继续。历史缺失标为待审查，不保证跨AI自动去重。交付前复查，交付后立即登记逐篇素材用途；资料引用与媒体复用分别判断。

## 用图像与文献建立分析

### 选题先通过视觉筛选

自动选题或面向小红书推荐时，先读取 [视觉选题筛选](https://github.com/zhutlarnold/art-tech-critique-skill/blob/main/skills/art-tech-critique/references/visual-selection.md)，实际查看候选的真实原图。美感、震撼感和手机首图辨识度都要有具体画面依据；思想深度、知名度或技术噱头不能抵消明显的视觉不足。未看图标记待评估，不把标题或网页文字当成视觉核实。

先交付候选原图/可打开的图片链接及简短判断：画面美感在哪里、什么细节有冲击力、缩小后主体是否清楚、批判是否有证据、推荐/待补图/不推荐。明显依赖长文解释才显出趣味的图像，不作为默认发布选题；缺合格候选时继续找或如实交付较少候选，不凑数。

用户指定作品时先说明视觉局限；明确要求分析它则继续，不擅自替换。不把抽象、概念艺术一概排除，也不把不适合本栏目说成没有艺术价值。不要为通过筛选生成替代图、制造现场效果或用夸张标题掩盖原图不足。

### 通过后再深入研究

读取 [研究方法](https://github.com/zhutlarnold/art-tech-critique-skill/blob/main/skills/art-tech-critique/references/research-method.md)。核对具体作品身份与版本，分开作品年份、照片年份、网页日期和展览日期。使用实际可用的检索工具，记录真实查询与访问情况；只检索本次问题尚缺的材料。无网络时使用用户资料并明确缺口，不假装检索成功。

先看原图，记录可见的构图、材料、尺度、颜色、界面、空间和观看条件；再查作者声明或直接访谈。把分析连成一条有依据的关系：作品细节如何产生表达，涉及什么具体技术或工业过程，哪些人的处境或关系值得追问。说明技术时解释它怎样运作、怎样进入作品；不以软件名、科技感或笼统的危害清单代替。

研究记录分清事实、作者明确意图、本文解读和未确认内容。作者系列声明不自动解释每个构图；机构解说不冒充作者原话。主要解读给出图像或文献前提，保留合理的另一种解释。艺术作品能提出问题，不能独自证明污染数值、普遍偏见、观众反应或传播效果。

## 写得自然，读者能理解并联系生活

全文写作或语气修改时读取 [写作与生活哲思](https://github.com/zhutlarnold/art-tech-critique-skill/blob/main/skills/art-tech-critique/references/writing-and-reflection.md)；需要具体例子时再看 [两篇案例复盘](https://github.com/zhutlarnold/art-tech-critique-skill/blob/main/skills/art-tech-critique/references/two-case-lessons.md) 与对应的已认可全文。

从读者能看见的细节进入，随着文章需要解释形式、技术与作者意图，再引出生活情景和可讨论的问题。这个顺序是可调整的写作思路，不能每篇机械套同样段落。

生活联系必须能回到作品的分析。例如油田引出使用物品与生产来源的距离；分类标签引出评价一件事与定义整个人的差别。类比注明是本文延伸，不冒充作者本意，不等同不同机制。用生活例子帮助理解，保留作品自身的艺术分析。

使用普通词、自然长短句和必要的技术解释。允许第一人称提出解读，但不虚构观展、采访或操作经历。删去空泛升华、重复过渡、名词堆叠和带着答案的反问；避免要求读者认错、内疚或选边。提问留出不同判断及其理由，数量按文章需要决定，不连续堆砌。

朗读检查并尝试用两句话复述：这件作品怎样表达，为什么这个问题与生活有关。写作审查不能保证所有读者都觉得没有 AI 感；没有读者反馈时不声称已经验证理解、互动或流量。

## 原图与交付

选可追溯的作品照、现场照或必要细节，取得文件后逐张查看。首图优先用通过视觉筛选、能清楚呈现作品的原图，其他图片补充尺度、细节、不同视角或论据；不为了增加张数放入空泛重复图。图数取决于论点，不固定六张或统一模板。核对图片中实际作品、版本与用途；其他作品不能写成主图局部，数据集页面不能写成工具即时输出。保留出处、作者和已知摄影署名，未知署名不猜。

使用真实原图，不用生成插画、气氛图或通用科技图替代作品。只有链接时明确尚未取得图片，不称作完整图片包。用户已要求直接使用时，不另设逐张授权确认流程，也不声称未经核实的权利或许可。

完整案例默认交付：标题、正文、少量相关标签；真实图片、顺序与图注；单独的研究依据和历史登记增量。未指定篇幅时约 800 字作为编辑起点，随内容调整，这不是平台字数上限。按用户输出位置保存，无指定时使用当前项目交付目录，不写死个人电脑路径。

需要分享文档时可提供单文件 HTML 或环境支持的 PDF/Word，检查全文、图注、图片和实际页面；不要把本机文件地址称作公开网络链接。网络发布需任务授权与实际可用服务。

## 最后验收

读取 [验收](https://github.com/zhutlarnold/art-tech-critique-skill/blob/main/skills/art-tech-critique/references/acceptance.md)，检查视觉适配、证据、艺术分析、技术关联、生活联系、自然语气、真实图片及旧稿差异。默认推荐的作品需同时满足图像适配与批判分析，不能用文字质量抵消视觉不足；用户指定分析的例外在交付中说明。Python 可用时用 `scripts/registry.py` 验证登记结构和重复预警；无 Python 按相同规则人工维护。它使用标准库，仅给已知历史的启发式提示，不决定事实真伪、审美质量或全网语义新颖性。

已有项目历史保留其他栏目与旧版本，登记本次实际研究和交付。用户认可、已交付与平台发布分开；无发布证据保持 unknown。完成每一步简要说明结果、检查依据和下一步，格式检查与脚本测试不能冒充独立模型或读者验证。

## references/material-reuse.md

# 素材防重复：同一项目、跨栏目检查

本规则用于新案例选材、封面和图片包交付。每次读取用户指定历史，否则读取当前项目case-research-state/registry.json。两个Skill和其他栏目使用同一项目总表，不能只查当前角度或包内示例；种子快照不会自动同步。

## 默认限制

- 新稿不使用已交付或已发布稿用过的原图、截图、海报、视频/动图或片段。封面与正文配图同样检查。
- 已被另一篇正在制作的稿件选定的素材，先标记待审查，避免再次分配；写入和交付前再次读取总表，保留其他任务记录。
- 更换文件名、压缩、尺寸、格式、镜像、局部裁切、加字或截取同一原视频，不会使它自动成为新素材。关联原素材并对照内容；文件哈希不同不等于未用过。
- 同一件作品的不同真实照片分别核对，不把整个艺术家或作品系列当作一张素材；同一原片的不同片段默认按同源素材审查，不凭时间段不同绕过限制。
- 官网、论文或技术文档可为核查重复查阅并引用；这不意味着文章可以再次分配它们已使用过的配图。查证来源复用与发布媒体复用分别记录。

## 写稿前的检查

1. 看已有图片记录和各篇analyses/delivery_files。记录素材是否已用、用了哪篇/哪个栏目/哪个版本，分开“曾下载”“已选定”“已交付”“已发布”。有记录不自动推导已发布。
2. 对照原图URL、来源页里的具体图像、真实文件SHA256及已知原素材ID。脚本的image_reuse预警先视为不可分配给新稿，复核用途后才能解除；不能只显示提醒就继续选用。
3. 实际查看疑似重复的画面，核对裁切、改尺寸、字幕、水印、视频内容/时间段与原始来源。现有脚本只识别哈希和URL，不自动识别全部近似图、视频片段或变换；视觉与同源判断仍须人工/模型复核。
4. 有明确旧用途的素材默认淘汰，优先寻找不同真实照片、不同作品或其他未使用且符合分析与视觉标准的素材。无法补齐时减少图数或报告缺口，不用生成图、重复图或改名图凑包。

## 允许沿用的范围

- 同一篇稿件修订、排版、转格式或制作同内容不同平台版，可沿用原素材，记为同一交付系列，不冒充新选题或新素材。
- 用户明确要求新稿比较、回顾或复用某张旧素材时，可按已有授权继续，注明原篇、复用目的与新增分析。不要再次请求已经给过的许可；“直接使用网络素材”本身不等于指定复用某张已交付图。
- 没有上述依据的新稿复用，不因“方便”“热门”或“适合封面”自动放行。先找替代素材，只有缺少会影响交付的必要信息时再询问。

## 记录与缺口

兼容现有images数组，在素材对象上可追加asset_id、media_type、original_source_url、original_sha256、derived_from，以及used_in对象。used_in以文章analysis_id为键，保存skill_name、status、role、delivery_files，必要时记reuse_reason与用户明确指令。每次增量更新保留旧用途和其他栏目；视频记录保留原片URL及片段范围。现有登记脚本对附加元信息只负责保留，不会自动核验其真实性或视频范围重叠。

示例元信息（按真实素材补齐，不复制示例指纹）：

```json
{"asset_id":"项目内稳定素材ID","media_type":"image","original_source_url":"https://example.org/original-photo.jpg","derived_from":null,"used_in":{"文章analysis_id":{"skill_name":"当前Skill名称","status":"delivered","role":"cover","delivery_files":["本篇交付文件"],"reuse_reason":null}}}
```

旧素材没有逐篇用途时回查对应稿件；尤其已交付作品的历史图，不能因used_in缺字段就认定未使用。无法确认的标为待审查，先选其他可确认素材。新项目明确没有历史时可建立空表，并把判断限定于这个项目。

材料不足、历史未取得或跨AI历史不同步时，不声称已完成全部素材去重；已知重复不能选进新稿，未确认项不得标为“保证未用过”。普通AI聊天应附最新总表与旧稿/素材清单；无文件写入能力时交付登记增量，由用户保存到同一总表，下次继续附上。

交付清单逐项写“未发现已知重复 / 同稿沿用 / 用户指定复用 / 待审查”，附核对依据、旧用途和例外原因。已交付即登记用途，不等到平台发布才记录；同时保持实际发布状态的证据边界。

## references/acceptance.md

# 案例与交付验收

按本次实际请求检查相关项目，不强制单项修改执行完整研究。

| 检查 | 验收依据 |
| --- | --- |
| 视觉选题 | 自动推荐前已看真实原图，美感、震撼感、手机首图辨识度均有具体依据；未看图不推荐，指定作品的视觉局限明确 |
| 研究问题 | 具体对象、版本和问题明确；已有文章的主字段与analyses已读取，缺口说明 |
| 艺术分析 | 重要判断回到实际图像的形式或观看关系，不只介绍作者和题材 |
| 技术关联 | 机制/基础设施具体，有来源，不把所有技术混在一起 |
| 作者意图 | 声明、访谈、机构解释与本文解读区分；引语可定位 |
| 论证 | 事实有来源、解读有前提，另一种解释改变适用范围或力度 |
| 标题与类比 | 标题不超过证据力度；不从构图推断传感器视野或实际运行，生活类比不等同不同技术机制 |
| 生活联系 | 至少在需要哲思时有具体生活情景，能说明与作品的联系与类比边界 |
| 讨论 | 读者能表达不同意见；没有预设罪过、情绪或显然正确的选项 |
| 语气 | 普通词解释清楚、段落自然、重复与空泛升华删去、不虚构经历 |
| 素材防重复 | 跨栏目总表已读取；已知旧媒体不进新稿，变换/裁切/同片截取已复核；同稿沿用或明确复用有依据，交付即登记用途 |
| 图片 | 实际逐张查看、身份/版本/顺序/出处/图注对应，取得与未取得分开 |
| 文档 | 全文保留、图注可读、无裁切误读；PDF/Word需实际渲染，HTML检查内嵌图像与内容 |
| 状态 | 研究、草稿、认可、交付、发布按证据分开；更新保留旧记录 |

格式与脚本验证不能代替主观质量判断。两个认可案例是规则来源，不能再把它们当独立保留测试。若开展跨AI验证，使用新案例与最少原始材料，先定义可观察的标准，不把目标答案喂给测试环境；得到真实输出后再评判，不虚构已验证结论。

最终交付简述本次完成、检查依据、未确认与下一步，不堆与请求无关的合规清单。

## references/examples/imagenet-roulette-evidence.md

# Trevor Paglen 的 ImageNet Roulette，结合其与 Kate Crawford 的联合研究背景；2019 年同期论文已记述此工具

核心问题：分类界面的图像语言怎样使人的判断显得像技术测量，并把观看者变成被分类的对象？

本篇结论：作品将后台分类呈现到人的肖像上，让类别如何定义人变得可见；它批判特定训练材料与分类关系，不能据此概括所有 AI。

## 图片顺序与用途

### roulette-authors

Kate Crawford 与 Trevor Paglen 使用 ImageNet Roulette 的展示图。图中的英文为系统分类标签。来源：Paglen Studio；页面未列摄影署名。

首图与形式分析证据。完整保留绿色人脸框和标签，让读者看到本文分析的界面语言。

可见依据：人脸边框、黑底绿字标签、人物肖像与背后的图像墙；标签是 newsreader 与 microeconomist

### roulette-labels

Paglen Studio 展示的 ImageNet 历史 person 类别页面，类别名包含 failure 和 loser。标签属于被批判的分类材料，不代表本文对照片人物的判断。

第二张机制背景图。呈现类别、图像和分类层级；明确这是历史数据集页面，不是工具的即时输出。

## references/examples/imagenet-roulette-post.md

AI给你贴的标签，谁先替它决定？

这张图里的两个人，被 AI 分别贴上了“新闻播报员”和“微观经济学家”的标签。绿框圈住脸，黑底绿字写出结果，看上去很像一份干脆的判断。

他们是 AI 研究者 Kate Crawford 和艺术家 Trevor Paglen。图中使用的是 Paglen 的艺术项目 ImageNet Roulette，它与两人对训练数据的联合研究有关。

这项工具使用 ImageNet 历史上的 person 类别训练分类模型。上传照片后，程序定位人脸，再给出分类标签。它能返回哪些答案，取决于训练材料和预先设置的类别。你看到的那个词，在照片进入系统之前，就已经存在于分类里。

第二张图是作者展示的数据集页面，其中有“失败者”这样的类别。看到这里，很难不迟疑一下：一张脸，凭什么能说明一个人的人生是否失败？这样的词一旦成为分类，就把某种对人的评价放进了技术流程。

作品的表达方式也很值得看。绿色方框把脸圈得很明确，短标签给出一个没有解释的结果。这种界面容易呈现出测量的样子：仿佛只要框得够准，旁边的判断也就有了依据。但定位到一张脸，离理解这个人还很远。

假如绿框里换成你的脸，观看的位置也会变。你原本在观察系统，现在却成了被它命名的人。这是我对作品参与方式的理解：它把藏在后台的分类规则，放到了一个你能认出的具体的人身上。

Paglen 在作品说明中把项目称为一次挑衅，希望显露训练材料中的问题。两人在 2019 年的《Excavating AI》中也讨论了这套分类。结合这些说明，我会把作品理解为一次对命名权的追问：类别由谁决定，被分类的人能否解释自己的经历，又能否提出异议？

需要记住，它针对的是特定的历史 person 类别。第二张是数据集页面，并非第一张工具的即时结果；这件作品也不足以证明所有 AI 都以同样的方式判断人。

生活里也有类似的时刻。一次考试没考好，和“你就是不行”，是两种分量完全不同的话。前一句说的是一件事，后一句却像要把一个人定下来。那张脸旁边的标签，让我们有机会重新想一想：我们平时是不是也会这样评价别人？

最后不妨换个设想：如果系统给你一个讨喜的标签，比如“成功者”，你还会要求它解释依据吗？我们可能很容易拒绝冒犯自己的判断，却欣然接受赞美。但一个标签让人高兴，是否就足以让它获得定义人的资格？

## references/examples/oil-post.md

油田被拍得很美，批判还成立吗？

如果先不看标题，这片金色的土地很容易让人多停留几秒。黑色的小形状排列在土坡上，一直延伸到远处。看清以后才发现：那是一台台抽油设备。

这是摄影师 Edward Burtynsky 的 Oil Fields #19ab，2003 年拍摄于美国加州 Belridge，属于他的《Oil》系列。

可以留意一下他怎样安排画面：天空只剩上方一条窄带，土地和设备几乎占满了视野。近处还能看清机器的结构，越往远处，机器越像重复的小点。单台设备或许并不起眼，密密铺开之后，却有了让人难以忽略的规模。

第二张 Oil Fields #27 里，道路沿着起伏的地形交织。抽油设备、管线和道路构成了开采系统，也重新安排了这片土地的用途。我们平时接触能源，大多是在使用它的时候；这两张照片把视线带到了原料被取出的地方。

暖色的土地、黑色设备和反复出现的线条，又让现场有了某种秩序感。这也让作品有些难以简单归类：画面可以很美，画面里的开采方式却仍然值得追问。

Burtynsky 在系列声明里谈到，工业成就曾令他惊叹，但石油带来的自由，也伴随着对环境的忧虑。他在总体创作声明中写到的吸引与排斥，恰好提供了一条理解这些照片的线索。

这也让我想到买东西时的选择：价格、外观、好不好用，都很具体；原料从哪里来、生产留下了什么，却不在眼前。由这片油田想到生活，我们享受一件东西的便利时，要不要也关心它是怎样来到手里的？

如果便利由许多人享受，代价却集中在某些地方，责任该怎样分配？按消费多少、获益多少，还是按谁更有能力改变规则？这张照片没有替我们作答，但它让这个问题有了一片具体的土地。

当然，漂亮的照片也可能让人停留在构图和色彩上。美感是否帮助我们理解了开采，还是把现场变成了一幅可供欣赏的风景，仍然可以讨论。仅凭照片，我们也无法知道当地究竟承受了多少污染。

再看这片金色的土地，你仍然可以觉得它美。但知道这些漂亮的纹理来自石油开采之后，你的欣赏会发生变化吗？我们能否一边赞叹照片里的秩序，一边质疑形成这种秩序的方式？

## references/history-and-dedup.md

# 历史登记与查重

读取用户现有登记优先。空表用于新项目；`assets/approved-cases.seed.json`仅在用户明确继续这些案例或要求导入时使用。本包种子只有这两篇已认可开发案例，不覆盖所有社团历史。作品ID跨栏目复用，新增文章使用唯一 `analysis_id`，把旧问题与旧结论保留在 `analyses` 对象中。

## 需要比较的层次

1. 对象：作者、已知别名、作品/版本/年份；同名不同版本先核对，Untitled不能自动合并。
2. 材料：已知来源URL、同源稿件、图片文件指纹及实际画面。不同文件指纹不证明图片内容新颖，来源复用也不等于稿件抄袭。
3. 文章：核心问题、主要结论、批判对象、机制、形式策略、证据、生活例子和伦理问题。比较主字段及所有 `analyses`，不同作品可能重复同一套论证。
4. 研究计划：已有来源能解决的问题不反复从零检索；按证据缺口查询，复核时说明理由；阶段性总结已知、未确认、下一项缺口。

先写比较表“旧问题与结论／本篇问题与结论／推理变化／新增证据与艺术分析／决定”。可给继续、补证、比较、续写、暂缓的判断，不因有重复就抹掉记录。历史缺问题或全文时明确无法完成哪层比较，不能用未命中代替查重成功。

## 素材使用限制

新稿的媒体素材按 [素材防重复规则](https://github.com/zhutlarnold/art-tech-critique-skill/blob/main/skills/art-tech-critique/references/material-reuse.md) 检查，image_reuse预警不能只提示后忽略。元信息记录原素材、衍生关系与逐篇used_in；旧图没有逐篇字段时回查交付稿，未确认不能当成未用。来源查证可以重复，发布配图另做限制。

## 数据结构

`schema_version: 1`，数组为 `cases`、`sources`、`searches`、`claims`、`images`。

- case 必需：`id`、`title`、`kind`、`artist`、`year`、`aliases`、`stage`、`publication`。artist/year未知用null；kind为artwork/product/artist_reference/format_reference。
- case 可有主字段 question/takeaway；逐篇记录在 `analyses`，键为唯一ID，值含 skill_name、angle、question、takeaway、stage、artistic_strategy、daily_anchor、discussion_question、claim_ids等。
- source 必需 id/url/source_type；已确认同源才用 evidence_family_id，访问情况另记。
- claim 必需 id/case_id/type/text/sources/premises/publishable；type为fact/artist_intent/interpretation/unverified。事实与意图要有来源，解读要有可追溯前提，未确认不能发布为已知事实；locator定位图像或文献。
- image 使用 source_url、case_id、sha256、role、caption等；没有真实文件不编造SHA。
- search 记实际日期、query、purpose、结果、访问失败或复查理由，不填猜测的检索总量。

stage 为 mentioned/researched/drafted/delivered/published，表示实际观察到的阶段；认可用 adoption 另记。publication 为 `{ "status": "unknown", "evidence": [] }`，确认发布才用 published_confirmed及证据。交付与用户认可不推导已发帖。

## 命令与安全更新

命令相对 Skill 文件夹。Python 3.10+，只用标准库。README有完整命令示例。

`init`创建且不覆盖；`check`验证结构/引用与前提；`assess`验证候选并只读预警；`merge`使用add或update，先验证整体结果，备份、写锁、指纹核对和原子更新。不删除活跃写锁，不用整文件覆盖共享表。

完整候选可写：


已有作品增加文章：

```json
{"cases":[{"id":"已有作品ID","analyses":{"新的analysis_id":{"skill_name":"art-tech-critique","angle":"艺术批判工业与科技","question":"本篇问题","takeaway":"本篇结论","stage":"delivered","artistic_strategy":"本篇形式分析","daily_anchor":"生活联系","discussion_question":"留给读者的问题","claim_ids":[]}}}}]}
```

## 脚本预警的范围

已知题名/别名与作者/年份用于身份和版本提示，不猜作者简称与新翻译。来源URL只去除已知追踪参数，保留有意义的版本信息。图像比较SHA与来源地址。

形式策略、生活类比、讨论问题和换词后的同义论证仍需阅读全文人工/模型复核。check只能验证已登记引用关系，不能证明来源真的支持主张。包内检查不检查全网，未完成历史比较时保留缺口。

## references/research-method.md

# 从作品到批判：研究方法

## 定位本篇问题

自动选题先按 [视觉筛选](https://github.com/zhutlarnold/art-tech-critique-skill/blob/main/skills/art-tech-critique/references/visual-selection.md) 查看原图，筛掉明显不适合本栏目首图的候选，再深入研究。初筛仍需核对作品与来源及批判方向，不把漂亮画面直接当作作者有批判意图。已指定作品或单项研究按请求范围继续，视觉适配不足另行说明。

研究前读取历史，区分作品复用与论点重复。用一句话写问题，再说明需要哪种证据，不从“科技有危害”这样宽泛的结论倒推作品。候选材料不足时缩小范围或保留缺口，而不是补写作者想法。

查询可依次围绕作品官网、作者声明/直接访谈、机构目录、必要的技术材料和相关研究展开，只补当前问题的缺口。记实际查询、日期、检索目的、访问状态与定位；要复查旧来源，写清复查版本、矛盾或图片身份的理由。不同网址的同源材料不算独立佐证，只有检索次数不能说明案例库存或研究覆盖率。

## 图像与机制一起读

先实际查看原图，把“看得见”与“需要外部材料才能知道”分开。例如看得见人脸框与标签，但分类模型的训练范围来自方法说明；看得见设备排列，但不能由照片得知污染浓度。

选本篇真正重要的形式细节：重复、尺度、颜色、取景、材料、界面、时序或参与关系。解释细节怎样改变观看或使某个社会关系可见；不要罗列所有艺术术语。网页再现不能冒充实际印相、展场尺度、声响或身体体验。

技术分析回答实际机制：原料/输入如何进入系统，系统怎样处理，产出怎样呈现，谁制定规则，观众怎样参与。摄影案例可分析基础设施与取景，算法案例区分检测、分类、身份识别；不要硬套同一传感器流程。

## 批判对象、作者与本文解读

说明批判针对哪一套过程、规则或关系，代价或排除可能怎样产生，以及资料支持到什么范围。区分个人、企业、制度、模型和数据集，避免把所有技术混成一个对象。

作者意图优先用声明与直接访谈。系列理念注明系列层面；机构文字注明是机构解释；无声明仍可做有依据的形式分析，但不能补写作者明确想法。引语要能定位，译文注明；没查到原话就不用引号。

在独立研究表中为事实与作者意图登记来源/定位，为解读登记可见图像或已确认主张作为前提。生活类比、假设和讨论问题记为本文延伸。推理不回到自身作证，不依赖未确认前提。

考虑一项真正相关的另一种解释：美感可能引人注意，也可能淡化代价；挑衅性模型可能揭示历史训练材料的问题，但不代表全部现实模型。反方应改变论点的范围或力度，不为假装平衡加一句“也有好处”。

## 研究停止与交付

当前问题的关键事实可定位、图像能支撑形式分析、主要解读有前提、版本矛盾已处理或明确保留时，可以进入写作。若核心技术或作者身份仍不确定，说明这一缺口怎样限制稿件，不无限反复检索。

发布稿保持易读，证据表与查询日志另附。文章不把艺术批判包装成科学实验证明，不从作者意图推导观众效果，也不声称未经测试的流量表现。

# 两篇已认可案例的生成经验

全文分别见 [Oil](https://github.com/zhutlarnold/art-tech-critique-skill/blob/main/skills/art-tech-critique/references/examples/oil-post.md) 与 [ImageNet Roulette](https://github.com/zhutlarnold/art-tech-critique-skill/blob/main/skills/art-tech-critique/references/examples/imagenet-roulette-post.md)，研究依据与图注见同目录证据文件。用户认可语气自然与生活联系后开始本 Skill 提炼；不表示已发布、已测传播或经过陌生读者盲测。

## Oil

主图为 Oil Fields #19ab，第二图是 Oil Fields #27，不能写成同一幅的局部。保留双联主图的接缝与整体。

形式：设备重复、近远尺度、窄天空、暖色土地和道路。机制：开采基础设施组织土地。作者依据：Oil系列声明和总体声明中的工业吸引、消费依赖与忧虑。本文解读：美感与质疑可以并存，可能吸引注意，也可能把现场审美化。

生活延伸：买东西关心用途与价格，也追问原料和生产过程；责任讨论保留个人与改变规则的能力，不强迫消费者为所有后果负责。最终结尾区分欣赏画面秩序与判断开采方式。

修改经验：原句“美感让我们看漏了什么”预设欣赏导致忽视，被用户指出生硬；改成知道景观来源后欣赏是否变化，更允许复杂感受。具体损害分布和污染浓度不由照片推断。

## ImageNet Roulette

主图是Crawford与Paglen使用工具的展示，另一张是历史数据集类别页面，不是主图工具即时输出。分类标签不当成两人的真实职业。

形式：肖像、人脸框、黑底绿字与简短标签，观众的照片进入流程后成为被命名对象。机制：历史person类别训练模型，定位与分类区分。作者依据：作品说明与联合研究，主张同源不能算两项独立实验。

本文问题：技术能够分类，与它是否有依据定义一个人，需要分别讨论。生活联系：考试一次没考好与评价“你就是不行”的差别；讨喜的“成功者”标签是讨论假设，不是作品实际输出。质疑负面与接受赞美时是否使用同一标准，留给读者判断。

范围：针对特定历史材料，不把作品当作全部当代AI的测试；未实际运行工具，不提供人脸上传实验。

## 后续视觉要求

两篇认可稿保留，认可自然语气不代表所有范例自动通过新的视觉标准。v1.1.0选题另作美感、震撼感和首图检查：油田原图有密度与空间秩序依据；ImageNet Roulette的界面图需要重新评估视觉适配。盐圈案例的试用反馈成为筛选失败经验，具体方法见 [视觉选题筛选](https://github.com/zhutlarnold/art-tech-critique-skill/blob/main/skills/art-tech-critique/references/visual-selection.md)。

## 可复用与不可机械复用

复用证据对应、形式与机制相连、作者意图分开、生活情景与可讨论矛盾。不复用固定图数、段落数、第一人称句式和结尾模板。读者反馈能检验自然语气，格式或“去AI检测分”不能替代。

## references/visual-selection.md

# 先看原图：视觉选题筛选

本模块用于自动选题、首图选择和发布适配检查；单项事实核查或改句不必重新跑完整筛选。默认服务于以真实作品原图吸引观看的小红书案例，而不是给所有艺术作品评艺术价值。

## 图像与研究同时成立

默认推荐要有两类依据：真实画面有美感与震撼感；作品与工业/科技批判的关系可分析、可查证。只满足概念有趣，或只满足漂亮，都不足以推荐。美感不限定为艳丽、整洁或讨喜；秩序、质感、光影、复杂构图、令人不安的形式同样可能成立。抽象作品可以有强烈视觉表达。

实际查看艺术家或机构的原图；有工具时取得图片并以手机首图接近的显示尺寸检查。没有工具只给待评估与补图需求，不虚称看过图。不使用虚构打分、收藏量或点击率证明适配。

| 维度 | 要寻找的画面依据 | 不足的情形 |
| --- | --- | --- |
| 美感 | 构图、色彩、光影、材质或节奏形成可描述的视觉组织 | 只能说“很高级”，没有画面细节支持；趣味完全来自说明文字 |
| 震撼感 | 尺度、密度、异常并置、空间包围、材料反差或可见运动产生明显视觉张力 | 作者名气或技术听起来厉害，但图片本身平淡 |
| 首图辨识 | 缩小后主要对象仍看得清，视线有落点，能看出至少一个值得继续观察的细节 | 关键对象很小、文字标签不可辨、画面杂乱或只有看完长说明才知道该看哪里 |
| 批判适配 | 具体形式能通向一个工业/科技关系，来源支持作者背景或本文解读 | 只有科技感、漂亮装置或宽泛道德口号，找不到作品依据 |
| 图片可用性 | 来源与版本明确，清晰度足以分析，首图与后续图用途有差异 | 只有低清缩略图、失效链接、来源不明图或必须大幅改造才能呈现核心对象 |

每项写“强/一般/弱/未评估”并附具体依据，属于本次编辑判断，不是统计评分。默认推荐应有清楚的美感、震撼感与首图辨识依据，且不存在批判或图片来源方面的关键缺口。明显弱项不能靠其他项平均抵消；一般项可以用更合适的真实视角复查，仍不清楚则保留或淘汰。

## 输出与取舍

给候选时优先附原图预览，环境不支持预览则给直达图片链接并说明。再简列作品/版本、上述判断、拟用首图、技术或工业问题、来源与取舍。用户要求N个时尽量提供N个合格候选；不足时明确实际数量，不为凑数推荐视觉不符的作品。

- **推荐**：原图有明显形式吸引力与冲击点，缩小仍清楚，批判关系可查证。可以深入研究。
- **待补图**：概念相关但未取得、未看过合适原图，或需要更清楚的真实视角。找到并查看后再判，不先写成推荐稿。
- **不推荐作为默认发布选题**：已经看过图，关键视觉维度仍弱。说明具体原因，保留研究记录，不用夸张标题或生硬哲思来补救。

用户指定作品，先说明局限及有依据的替代图可能；如果明确要分析这个作品，继续交付并标注例外，不反复要求确认。普通裁切可以改善落点，但应保留作品关键关系，提供裁切范围与原图；不能把小主体重做成虚构的巨大现场。视频或动态作品若依赖时间变化产生冲击，要查看真实片段再判断；静帧一般并不证明完整作品没有冲击力，本次图文资料不足时说明这一限制。

## 从试用反馈得到的修正

用户试用《Autonomous Trap 001》后指出画面不满足美感和震撼感要求。已查看的两个原图视角中，汽车/盐圈占整张照片较小面积；第二张没有汽车，作品趣味主要依赖交通规则与机器行为的解释。这是其目前图片不适合本栏目默认首图的编辑判断，不是对艺术价值或所有动态资料的否定。

它保留为“能分析、却不应只凭概念自动推荐”的回归案例。已认可的油田照片可用设备密度、景深与暖色秩序解释视觉吸引力。《ImageNet Roulette》的已认可稿保留，但不能据此给新选题免检：现有图以界面和文字为主，首图冲击力须重新判断，不能假定每个开发例子都满足新标准。

视觉适配能改善选题决策，不能保证点击、读完、互动或流量。未经真实投放和读者反馈，不写“必爆”“人人震撼”。

## references/writing-and-reflection.md

# 自然写作与生活中的哲思

## 写给谁

面向愿意了解艺术、但未必知道艺术术语或技术细节的普通读者。读完应能复述作品怎样表达，以及问题为什么与自己有关。约800字只是起稿参考，不能为凑长度删掉关键证据或堆重复句。

## 让叙述有人的判断

从一个可见的画面细节开始，具体说清再解释。重要技术用普通词说明；只在确实有用时给术语。叙述可有“我会这样理解”的判断，不需要每段机械标注“我们的解读”。作者声明与本文解读在语义上清楚分开，证据留在单独研究依据。

标题也接受事实核查，力度不能超过材料。只有照片或机构解说时，不把推测写成确定的运行事件，不把“害怕”“不敢”等拟人词当作机器心理解释。可以提出可回答的悬念，但不能以戏剧性标题补偿原图视觉不足。不能从拍摄机位推断机器传感器的完整视野、代码行为或参与者想法。

第一人称只表达作者当下的理解，不虚构“我在展览现场”“我采访过”“我亲自试过”等经历。自然语气不是增加网络梗、感叹号或故意写错字。

段落跟随内容，句子有长有短。不要求每篇先写艺术家履历，不固定“简介—技术—意义”标题，也不每篇使用相同开头或结尾。删去空泛过渡、术语串联和一口气给出的结论。

## 从作品到生活，再到问题

选一个确实相关的生活情景，说明它与作品共享的矛盾，再提能讨论的问题。问题要能回到作品，换任意作品都成立的“科技是否让人幸福”过于宽泛。类比不是机制等同，假设不是作品实际输出。

生活机制的事实也要核对。例如共享电动车的电子围栏与机器读取地面标线，可以类比为“由规则划定可行动的范围”，但不能写成同一种识别机制；不能把某运营商、某车型的功能泛化到所有共享单车。没有记录的运行条件或读者体验，改为明确假设或说明未知。

两个已认可的例子：

- 油田：设备和道路形成开采系统 → 消费者通常接触成品，与来源和过程有距离 → 使用便利时如何关心生产代价、责任如何分配。由此延伸到买东西的选择，不声称商品来自这张照片中的油田。
- 分类：肖像与评价性标签叠加 → 一个类别可能覆盖人的复杂经历 → “这次考试没考好”与“你就是不行”的区别。进一步假设讨喜的标签，讨论我们是否仍然要求依据。

生活例子不挤掉艺术分析；不能只靠“AI给人贴标签”就忽略人脸框、视觉语言和观众位置，也不能只说环保而不解释油田照片的构图与美感。

## 允许复杂感受

提问邀请读者说明判断依据，不安排一个显然正确的答案。避免把欣赏说成过错、把享受便利说成不配批判，或让读者只能在两个极端之间选边。可以提出矛盾，也允许“同时存在”“取决于条件”或暂时无结论。

已被用户指出的问题：

> 但如果看完之后，只留下“真好看”，这份美感又让我们看漏了什么？

这句话预设美感造成忽视，带有责备。后来认可的处理：

> 再看这片金色的土地，你仍然可以觉得它美。但知道这些漂亮的纹理来自石油开采之后，你的欣赏会发生变化吗？我们能否一边赞叹照片里的秩序，一边质疑形成这种秩序的方式？

这是说明判断的样例，不能把同一句套进每篇。提问数量不固定；保留有新增思考的句子，删掉重复追问。

## 修改与审稿

只要求语气修改时保留已核对事实、图注和核心论点。只有原句本身有事实/推理问题才连同含义修订，并说明理由。不要为“去AI味”删除作者意图的出处或把猜想改成事实。

读一遍全文，再尝试两句话复述。检查：是否需要术语才能理解？转入生活时是否突兀？问题是否带责备？是否把所有段落写得同样长？同一解释是否重复三遍？有没有空泛的最后升华？

可以改善可读性，不能承诺每位读者都察觉不到AI参与，也不能通过检测器分数证明真人写作。若要验证理解，请普通读者复述并指出不明白的句子；若要评价互动，使用实际发布反馈，不虚构数据。
